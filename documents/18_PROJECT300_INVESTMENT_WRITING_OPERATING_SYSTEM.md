# 18_PROJECT300_INVESTMENT_WRITING_OPERATING_SYSTEM

## 1. 문서 목적

이 문서는 Blogger와 Project300 Tistory에 발행할 급등포착 투자 글을 실제 운영자 글처럼 만들기 위한 상위 운영 명세다.

목표는 오래된 글의 말끝이나 감탄사를 흉내 내는 것이 아니다. 매일 달라지는 시장 자료와 운영자의 실제 판단을 구분해서 수집하고, 그날만 쓸 수 있는 중심 이야기를 만든 뒤, 기존 글의 설명 방식과 리듬으로 편집하는 것이다.

이 문서가 확정되기 전에는 단편적인 문구 추가를 말투 개선으로 간주하지 않는다. 이후 프롬프트, 생성기, 검수기, UI는 이 문서를 기준으로 구현한다.

## 2. 입력 자료에서 얻은 핵심 인사이트

### 2.1 사람처럼 보이는 글의 핵심

사람이 쓴 느낌은 `ㅎㅎ`, `ㅠㅠ`, `자. 그럼`, `저는` 같은 표현에서 만들어지지 않는다.

다음 네 가지가 있어야 한다.

1. 그날 실제 화면에서 발견한 구체적인 사실
2. 다른 후보와 비교해서 내린 선택
3. 실제로 한 행동 또는 하지 않은 이유
4. 다음에 판단을 바꿀 구체적인 조건

표현 사전은 이 재료를 기존 Project300 글처럼 정리하는 장치다. 없는 경험이나 판단을 만드는 장치가 아니다.

### 2.2 현재 생성물에서 AI 흔적이 강한 이유

현재 구현은 다음 문제를 가진다.

- 종목명과 숫자만 바꾸고 같은 판단 순서를 반복한다.
- `진입가 -> 목표가 -> 손절선 -> 뉴스 -> 아쉬운 점 -> 정리`가 종목마다 반복된다.
- 실제 운영자 판단이 없는데도 `저는`, `제 기준에서는`을 붙인다.
- 비슷한 금융주도 각각 같은 분량으로 분석한다.
- RSS, 자동 수집, 기사 전문 미저장 같은 내부 작업 설명이 발행 본문에 섞인다.
- 시스템 산식으로 만든 진입가와 손절선을 차트 지지선처럼 설명할 위험이 있다.
- 휴장일에도 `오늘 장`, `장중` 같은 표현을 쓸 수 있다.
- TOP 목록, 종목, ETF, 뉴스, 공시, FAQ, 홍보, 면책을 모두 넣어 글의 중심이 흐려진다.
- 단순 키워드 출현 횟수가 말투 점수를 높여, 반복 문장이 오히려 검수를 통과할 수 있다.

### 2.3 기존 Project300 글에서 유지할 요소

- 정중한 설명체를 기본으로 한다.
- 어려운 내용을 쉬운 말로 다시 풀어준다.
- 질문하고 직접 답하는 흐름을 필요한 곳에 쓴다.
- 결과뿐 아니라 실패, 망설임, 보완할 점을 숨기지 않는다.
- 숫자는 나열하지 않고 판단에 어떤 의미가 있는지 설명한다.
- 짧은 문단과 긴 문단을 섞는다.
- 다음 행동이나 다음 기록으로 마무리한다.
- 감탄, 괄호, `ㅎㅎ` 같은 표현은 실제 맥락이 있을 때만 제한적으로 쓴다.

### 2.4 그대로 사용하지 않을 요소

- 모든 글을 `오늘은 ... 확인해 보도록 하겠습니다`로 시작하지 않는다.
- 모든 종목에 `제가 먼저 보는 부분`을 붙이지 않는다.
- 과거 글의 오탈자나 오래된 표현을 인위적으로 복제하지 않는다.
- 모든 글을 같은 소제목, 같은 표, 같은 결론으로 만들지 않는다.
- SEO 키워드를 제목과 첫 문단에 기계적으로 쌓지 않는다.

### 2.5 기존 가이드와 구현의 충돌 목록

| 현재 규칙 또는 구현 | 문제 | 새 기준 |
|---|---|---|
| `저는`, `확인`, `자. 그럼` 출현 시 voice score 가산 | 반복할수록 점수가 올라갈 수 있음 | 1인칭은 JUDGMENT/ACTION 출처가 있을 때만 통과 |
| 모든 종목에 차트, 신호, 뉴스, 아쉬운 점, 다음 체크 적용 | 종목명과 숫자만 바뀐 동일 구조 생성 | 종목마다 역할과 질문을 다르게 배정하고 유사 종목은 비교 |
| 10개 deterministic 문단 패턴 순환 | 문장만 달라지고 판단 구조는 동일 | 표현 패턴은 outline과 실제 판단이 정해진 뒤 제한적으로 사용 |
| `자료를 먼저 모아보면`과 수집 상태를 본문 요약으로 반환 | 내부 작업 메모가 독자용 문장에 노출 | 수집 상태는 editorReview, 확인된 사실만 publish body로 분리 |
| 진입가·목표가·손절선 수치만 있으면 차트 해석 생성 | 시스템 산식을 객관적 지지·저항으로 오인 가능 | 산출 유형을 필수로 기록하고 SYSTEM 값으로 명시 |
| `오늘`, `장중`, `내일`을 marketDate 중심으로 생성 | 주말·휴장일과 표현 충돌 가능 | 작성 시각, 데이터 기준일, 시장 상태, 다음 거래일을 별도 계산 |
| 제목에 날짜·급등포착·종목 2~3개를 모두 강제 | 검색용 자동 제목처럼 보일 수 있음 | 검색형과 기록형 제목을 만든 뒤 실제 중심 판단과 맞는 제목 선택 |
| heading/image/link 수량 중심 SEO 점수 | 내용이 없어도 형식만 채우면 통과 | 출처 완전성, 문단 고유성, 검색 의도 충족을 함께 검수 |
| 동일 생성물이 자기 글을 다시 검수 | 생성 논리를 합리화할 가능성 | 분석기, 작성기, 독립 검수기를 분리 |
| 모든 자료를 최대한 본문에 포함 | 길지만 중심이 없는 글 생성 | 결론에 영향을 주지 않는 자료와 ETF는 생략 |
| GPT rewrite가 말투와 흐름만 일괄 수정 | 잘못된 구조와 근거 없는 판단을 유지할 수 있음 | 사실/구조 검수를 먼저 통과한 본문만 말투 편집 |

## 3. 최종 목표

최종 생성물은 다음 조건을 동시에 만족해야 한다.

### 3.1 사실 목표

- 가격, 날짜, 신호, 점수, 기사, 공시에는 출처와 기준 시각이 있다.
- 확인되지 않은 수급, 뉴스 내용, 운영자 행동을 만들지 않는다.
- 시스템 계산값과 객관적인 시장 사실을 구분한다.
- 작성일, 데이터 기준일, 다음 거래일을 구분한다.

### 3.2 글 목표

- 한 글에는 중심 판단이 하나만 있다.
- 비슷한 종목은 비교하고, 성격이 다른 종목만 별도로 깊게 본다.
- 종목마다 다른 질문과 역할을 갖는다.
- 독자는 숫자 목록이 아니라 작성자의 선택 과정을 읽게 된다.
- 글의 40~60%를 덜어내더라도 중심이 선명한 글을 우선한다.

### 3.3 말투 목표

- Project300 기존 글의 존댓말 설명형 문체와 리듬을 따른다.
- 실제 판단이 있을 때만 1인칭을 쓴다.
- 문단 길이, 소제목 형태, 전환 방식이 획일적이지 않다.
- 상투 문장과 반복 결론이 없다.
- 종목명과 숫자를 지워도 다른 종목에 붙일 수 있는 문단은 남기지 않는다.

### 3.4 채널 목표

- Blogger는 당일 시장 전체를 빠르게 훑는 Daily Brief 역할을 유지한다.
- Tistory는 비교, 판단, 매매 조건을 깊게 기록하는 개인 투자 기록 역할을 가진다.
- 같은 자료를 사용하더라도 제목, 중심 질문, 구조, 이미지 선택, 결론이 달라야 한다.

## 4. 정보 분류 계약

모든 입력은 본문 작성 전에 다음 네 종류로 분류한다.

| 분류 | 의미 | 본문 사용 조건 |
|---|---|---|
| `FACT` | 시간과 출처가 확인된 시장 데이터, 기사, 공시 | 출처와 기준 시각이 있을 때 |
| `SYSTEM` | 급등포착이 계산한 점수, 상태, 진입가, 목표가, 손절선 | 시스템 값임을 숨기지 않을 때 |
| `JUDGMENT` | 운영자가 직접 말하거나 승인한 생각 | 입력 원문 또는 승인 기록이 있을 때 |
| `ACTION` | 보유, 매수, 매도, 대기, 패스 등 실제 행동 | 운영자가 직접 제공한 경우에만 |

`JUDGMENT`나 `ACTION`이 비어 있으면 AI가 채우지 않는다. 이 경우 본문은 객관적인 관찰과 다음 확인 항목까지만 쓸 수 있다. `저는 매수하지 않겠습니다` 같은 문장을 임의로 만들지 않는다.

## 5. 작성 전 데이터 패키지

본문 생성 전에 `InvestmentWritingEvidencePack`을 만든다.

### 5.1 시장 기준

- 작성 시각과 시간대
- 데이터 기준 시각
- 요일
- 국내장 개장, 장전, 장중, 장후, 휴장 상태
- 직전 국내장 흐름
- 직전 미국장 흐름
- 다음 거래일
- 환율, 금리, 지수, 원자재 중 글의 결론에 영향을 주는 항목

### 5.2 종목 기준

- 종목명과 코드
- 업종과 테마
- 현재가와 가격 기준 시각
- 최근 신호 날짜와 횟수
- 급등포착 점수와 상태
- 시스템 진입가, 목표가, 손절선 및 산출 유형
- 이동평균선, 볼린저밴드, 거래량 등 실제 확인 가능한 차트 특징
- 외국인, 기관 등 실제 출처가 있는 수급
- 최근 기사와 공시의 제목, 날짜, 출처, URL
- 확인되지 않은 정보 목록

### 5.3 ETF와 교차시장 기준

- ETF 상위 목록과 섹터
- 최근 신호와 수익률
- 종목 결론에 실제 영향을 주는 ETF만 선택
- 선물·옵션 신호가 실제로 준비된 경우에만 교차 해석

### 5.4 운영자 판단 원장

매일 최소한 다음 입력을 받을 수 있어야 한다.

```text
오늘 화면을 보고 처음 든 생각:
가장 눈에 들어온 종목 또는 흐름:
비슷해서 하나로 묶을 후보:
굳이 보지 않아도 된다고 생각한 후보:
현재 보유 여부:
오늘 실제 행동:
지금 행동하지 않은 이유:
가장 걸리는 점:
다시 볼 조건:
제외할 조건:
과거 비슷한 경험:
꼭 살릴 표현:
```

웹에서는 짧은 텍스트 입력을 우선 지원하고, 후속 단계에서 30~60초 음성 메모 변환을 검토한다.

## 6. 생성 파이프라인

### 6.1 1단계: 증거 수집기

본문을 만들지 않는다. FACT와 SYSTEM 자료를 수집하고 출처, 시각, 누락 여부를 기록한다.

결과:

- evidence pack
- 확인되지 않은 정보
- 사용할 수 없는 내부 메모
- 날짜와 계산 오류

### 6.2 2단계: 판단 설계기

자료와 운영자 판단 원장을 이용해 글의 중심을 하나 정한다.

결과:

- 중심 판단 한 문장
- 비교할 종목 그룹
- 별도로 볼 종목
- 표에만 남길 종목
- 생략할 ETF와 자료
- 각 구간의 FACT, SYSTEM, JUDGMENT, ACTION 배치
- 추가 입력이 필요한 항목

이 단계는 본문을 쓰지 않는다.

### 6.3 3단계: 구조 편집기

제목 후보와 소제목별 역할을 만든다. 소제목마다 다음을 지정한다.

- 이 구간에서 답할 질문
- 사용할 사실과 시스템 값
- 사용할 실제 판단과 행동
- 관련 이미지와 출처
- 문단 수 범위
- 이전/다음 구간 연결 방식
- 사용하지 않을 상투 문장

### 6.4 4단계: 문단 작성기

글 전체를 한 번에 쓰지 않고 역할별 문단 묶음으로 작성한다. 같은 역할의 승인된 과거 예문 2~4개만 참고한다.

문단 작성기는 새로운 사실, 경험, 판단, 행동을 만들 수 없다.

### 6.5 5단계: 전체 리듬 편집기

문단을 합친 뒤 다음을 편집한다.

- 같은 결론 반복 삭제
- 같은 문장 길이와 문단 구조 해소
- 비슷한 종목 문단 통합
- 불필요한 FAQ와 ETF 구간 삭제
- 제목과 본문 중심 일치
- 채널별 중복 제거

이 단계는 사실을 추가하지 않는다.

### 6.6 6단계: 독립 검수기

작성에 사용한 호출과 별도의 검수 호출을 사용한다.

검수 순서:

1. 사실과 계산 검수
2. FACT/SYSTEM/JUDGMENT/ACTION 출처 검수
3. 날짜와 시장 상태 검수
4. 내부 작업 메모 유출 검수
5. 구조와 반복 검수
6. Project300 말투 검수
7. AI 흔적 검수
8. SEO와 링크 검수

검수 결과는 발행 본문과 분리된 `editorReview`에 저장한다.

## 7. 프롬프트 자산 구성

프롬프트 하나에 모든 작업을 넣지 않는다.

### 7.1 고정 프롬프트

- FACT/SYSTEM/JUDGMENT/ACTION 계약
- 없는 정보 생성 금지
- 내부 메모 발행 금지
- Project300 공통 목소리
- 채널별 역할
- 투자 표현 안전 기준

### 7.2 단계별 프롬프트

- evidence analysis prompt
- center judgment and grouping prompt
- outline prompt
- section writing prompt
- rhythm editing prompt
- fact review prompt
- style review prompt
- anti-AI review prompt

### 7.3 예문 저장 방식

승인된 실제 글만 기능별 예문으로 저장한다.

```text
voice-corpus/
  core-voice.md
  forbidden-patterns.md
  section-patterns.md
  examples/
    opening/
    easy-explanation/
    stock-comparison/
    chart-interpretation/
    news-connection/
    failure-and-doubt/
    action-condition/
    closing/
```

각 예문은 채널, 카테고리, 문단 역할, 길이, 감정 강도, 승인 여부를 태그로 가진다. AI가 만든 미승인 초안은 예문으로 축적하지 않는다.

## 8. 발행 금지 표현과 내부 메모

다음 표현은 발행 본문에서 차단한다.

- `RSS 검색 결과`
- `자동 수집 결과`
- `기사 전문은 저장하지 않고`
- `검토 후보`
- `자료를 먼저 모아보면`
- `검색 결과가 충분하지 않습니다`
- `위 차트에서 제가 먼저 보는 건`
- `첫 번째 체크는`, `두 번째는`, `세 번째는`
- `한 번 더 차트를 열어볼 이유`
- `목표가만 보면 글이 달콤해지지만`
- `아쉬운 점도 있습니다`
- `정리하면 OOO은`

내부 수집 상태와 부족한 출처는 `editorReview`에만 남긴다.

## 9. 최종 검수 체크리스트

### 9.1 필수 차단 항목

하나라도 실패하면 자동 발행할 수 없다.

- [ ] 작성일, 데이터 기준일, 시장 상태가 맞다.
- [ ] 가격과 수익률 부호 계산이 맞다.
- [ ] 기사와 공시에 제목, 날짜, 출처, URL이 있다.
- [ ] SYSTEM 값을 FACT나 차트 지지선으로 설명하지 않았다.
- [ ] 확인되지 않은 수급과 운영자 행동을 만들지 않았다.
- [ ] 내부 자동화 문구가 본문에 없다.
- [ ] 수익 보장과 직접 매수/매도 지시가 없다.
- [ ] 이미지, 숫자, 링크가 본문 주장과 일치한다.

### 9.2 사용자 말투 항목

- [ ] 실제 화면이나 그날의 구체적인 사실에서 시작한다.
- [ ] 운영자의 실제 판단 또는 선택이 드러난다.
- [ ] 1인칭 표현 뒤에 판단 근거가 있다.
- [ ] 문단 길이와 말끝이 균일하지 않다.
- [ ] 질문형, 설명형, 짧은 판단 문장이 자연스럽게 섞인다.
- [ ] 감탄사와 말버릇이 과도하지 않다.
- [ ] 승인된 예문과 같은 설명 방식이지만 문장을 복제하지 않았다.

### 9.3 반복과 AI 흔적 항목

- [ ] 종목명과 숫자를 가려도 각 종목 문단을 구별할 수 있다.
- [ ] 종목마다 같은 분석 순서를 반복하지 않는다.
- [ ] 비슷한 종목은 비교 구간으로 묶었다.
- [ ] 같은 문구가 두 번 이상 반복되면 필요한 한 번만 남겼다.
- [ ] 모든 소제목이 같은 형태가 아니다.
- [ ] 결론이 서론과 본문을 다시 요약하는 데 그치지 않는다.
- [ ] 그날만 가능한 사실, 판단, 행동, 다음 조건 중 하나도 없는 문단은 삭제했다.

### 9.4 SEO 항목

- [ ] 제목이 실제 본문 중심과 맞는다.
- [ ] 날짜, 주요 종목 또는 섹터, 검색 의도가 자연스럽게 들어간다.
- [ ] 첫 문단에 핵심 주제와 주요 이름이 억지 없이 나온다.
- [ ] H2가 검색 의도와 실제 내용을 함께 설명한다.
- [ ] 급등포착, 기사, 공시 링크가 적절한 문맥에 있다.
- [ ] 이미지 alt와 caption이 이미지의 역할을 설명한다.
- [ ] Blogger와 Tistory가 같은 글의 문장 치환본처럼 보이지 않는다.

## 10. 정량 합격 기준

기존의 단순 키워드 점수 대신 다음 게이트를 사용한다.

| 영역 | 합격 기준 |
|---|---|
| 사실/계산 | 차단 오류 0건 |
| 출처 | 기사·공시 사용 항목 100%에 날짜/출처/URL |
| 내부 메모 | 발행 본문 노출 0건 |
| 판단 출처 | 1인칭 판단 100%가 JUDGMENT/ACTION 입력과 연결 |
| 종목명 치환 | 일반 문단 경고 0건 또는 편집자 승인 |
| 반복 | 금지 핵심 문구 0건, 동일 시작구 2회 이하 |
| 구조 다양성 | 종목별 역할과 질문이 서로 다름 |
| 채널 중복 | 제목과 중심 구조가 다르고 장문 문단 직접 중복 없음 |
| AI 흔적 검수 | 10개 항목 중 8개 이상 통과, 차단 항목 0건 |
| 최종 상태 | `publishReady`는 모든 필수 게이트 통과 후에만 true |

점수는 참고용이다. 사실 오류, 판단 조작, 내부 메모 유출, 반복 템플릿은 총점이 높아도 차단한다.

## 14. 이번 작업의 종료 조건

다음 조건이 충족되어야 전체 작업을 완료로 본다.

- 챗에서 얻은 방법론이 문서, 타입, 생성 단계, 검수 단계에 모두 반영됐다.
- 말투 사전만으로 결과를 통과시키지 않는다.
- 생성 결과에는 자연스러운 블로그 말투 2차 검수를 항상 적용한다. `한 번만 보겠습니다`, `흐름을 정리합니다`, `유지되는지 확인하겠습니다`처럼 보고서식으로 굳는 표현은 독자에게 함께 살펴보자고 말하는 문장으로 제한적으로 보정한다.
- 2차 말투 보정은 숫자, 날짜, 표, 링크, 이미지 참조와 사실 관계를 변경하지 않는다.
- 2차 보정 뒤에도 어색한 문장이 남으면 준비된 말투 사전과 문제 코드만 포함한 최소수정 프롬프트를 GPT CLI `style_rewrite` 라우트로 보낸다.
- 말투 디테일은 단독 발행 차단 사유가 아니다. GPT CLI가 준비되지 않았거나 결과가 숫자·날짜·표·링크·이미지 참조를 바꾸면 후보를 채택하지 않고 deterministic 교정본으로 계속 진행한다.
- 실제 판단이 없으면 실제 판단처럼 쓰지 않는다.
- 반복 템플릿과 내부 메모를 자동으로 차단한다.
- 새 후보가 기존 후보보다 정보 밀도와 구별 가능성이 높다.
- 사람이 최종 결과를 읽고 `종목명만 바꾼 AI 글`로 느끼지 않는다.
- 승인 전에는 Blogger/Tistory 외부 발행을 수행하지 않는다.

## 16. 공통 오케스트레이터 적용 상태

`investment_writing_orchestrator_v1`은 다음 대상을 동일한 `evidence -> preflight -> outline -> generate -> review -> repair -> re-review -> gate` 공정으로 처리한다.

- Blogger Daily Brief
- Tistory 오늘의 관심종목 리뷰
- Tistory 종목별 신호 집중분석
- Tistory ETF 섹터 흐름 리뷰
- Tistory 선물·옵션 시그널 기록

선물·옵션 대상은 공정과 카테고리에 등록되어 있다. 값과 전략 성과는 `https://upsignal.co.kr/api/v1/futures/board`의 `timeframe`·`code` 구조화 응답을 우선 사용하고, `https://upsignal.co.kr/futures` 화면 자동화는 신호차트 캡처와 API 장애 시 fallback에 사용한다. 코스피200, S&P500, 나스닥, WTI, 금, EUR/USD 중 데이터가 안정적으로 잡힌 항목만 증거팩에 넣고, 3개 미만이면 `futures_options_signal_source_not_ready`로 생성과 발행을 차단한다. 주식이나 ETF 자료를 선물 신호처럼 대체하지 않는다.

선물 글의 본문은 상품별 지표를 일일이 설명하지 않는다. 표는 한 번만 쓰고, 이후에는 미국 지수 선물, 코스피200 선물, 원자재/환율, 국내 종목/ETF 연결 순서로 시장 브리핑처럼 풀어쓴다. 반복적인 `현재가는/진입가는/목표가는/손절선은` 문단은 deterministic anti-AI review에서 감점한다.

선물 evidence 선택은 `60분봉 열린 포지션 -> 240분봉 열린 포지션 -> 10분봉` 순서다. 나스닥, S&P500, KOSPI200을 우선 노출하고 같은 선택 상태로 상세 차트를 캡처한다. 표에는 현재 등락과 별도로 글 작성 시점 미실현 손익(pt), 선택 시간봉, 공개 가능한 전략명 또는 진입 방향을 기록한다. 미실현 손익은 확정 성과가 아니며 생성 시점 snapshot으로만 사용한다.

시간대별 선택은 `daily-brief/market-report-session.ts`가 담당한다. 아침은 미국 야간 신호, 한국장 장중/마감은 KOSPI200 우선, 미국 장중은 나스닥/S&P500 우선으로 분리한다. 한국장 세션에서 KOSPI200에 열린 포지션이 없으면 나스닥과 S&P500을 먼저 보여준다.

한국장 외국인 수급은 `UPSIGNAL_MARKET_FLOW_URL`로 설정된 구조화 API가 있을 때만 선택적으로 사용한다. 포함 조건은 `observedAt`, `foreign.spotNet`, `foreign.futuresNet`, `foreign.callOptionsNet`, `foreign.putOptionsNet`이 모두 존재하는 경우다. 하나라도 없거나 요청이 실패하면 수급 표와 관련 해설 전체를 생략하고, 글 생성과 발행은 다른 검증된 자료로 계속 진행한다. HTML이나 임의 화면 문구에서 숫자를 추정하지 않는다.

`GET /api/automation/daily-brief/market-report-readiness`는 네 세션의 우선순위와 수급 source 설정 여부를 read-only로 반환한다. `GET /api/automation/publication-schedule`은 Blogger 5개와 Tistory 7개 슬롯의 평일 편성, 실행기 설정, 날짜+슬롯 실행 이력을 반환한다. 추가 Blogger 슬롯은 투자 글쓰기/HTML 품질/Blogger guarded publish 체인을 재사용하고, Tistory 슬롯은 카테고리별 생성 후 문체·SEO·이미지·HTML 검수를 통과한 글만 반복 발행 승인 큐에 넣는다. 이미 성공한 날짜+슬롯은 재실행하지 않으며, 한국장 수급처럼 필수 원천이 없으면 해당 슬롯만 차단한다.

생성 후 deterministic 보완기는 내부 작업 문구, 근거 없는 1인칭, 금지 문구, 중복 문단을 제거한 뒤 동일 검수기로 다시 평가한다. 최종 `autoPublishEligible=true`가 아니면 Daily Brief draft-save/publish 자동화는 시작되지 않는다.
