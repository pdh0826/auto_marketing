# 17_PROJECT300_TISTORY_STYLE_SEO_GUIDE

## Purpose

project300 티스토리 글은 Blogger Daily Brief를 그대로 옮기는 채널이 아니다.

이 채널은 기존 `project300.tistory.com` 글처럼 개인 투자자가 차트, 시스템 신호, 뉴스, 공시를 보면서 생각을 풀어내는 분석 기록형 글을 목표로 한다. SEO는 적용하되, 검색어를 기계적으로 넣는 글이 아니라 독자가 실제로 읽을 만한 설명형 글이어야 한다.

## Reference Sources

스타일 참고는 공개된 기존 project300 글의 말투와 설명 방식을 기준으로 한다. 본문 문장을 복제하지 않고 아래 요소만 스타일 프로필로 사용한다.

- `MACD지표와 시스템트레이딩 로직 만들기`
- `Stochastics(스토캐스틱) 지표와 시스템트레이딩 로직 만들기`
- `시스템트레이딩 운영 3년간의 기록 그리고 그후`
- `Crude Oil 시황 및 시스템트레이딩 매매신호` 계열 기록
- 사용자가 대화에서 제공한 개인 투자 블로그 예시 문체

## Voice Profile

- 리포트체보다 개인 투자 블로그 기록체를 쓴다.
- `저는`, `제 기준에서는`, `개인적으로는`, `자 그럼`, `이 부분은` 같은 1인칭 설명을 허용한다.
- 숫자를 먼저 나열하지 말고, 왜 그 숫자를 보는지부터 설명한다.
- 차트, 신호, 뉴스, 공시를 따로 던지지 말고 `그래서 이 종목을 왜 다시 보는지`로 연결한다.
- 좋게 보이는 부분과 아쉬운 부분을 함께 적는다.
- 질문형 문장과 짧은 문단을 섞어 독자가 따라오게 만든다.
- 욕설, 조롱, 수익 보장, 확정 급등 표현은 금지한다.

## Structure Filter

권장 구조:

1. 오늘 왜 이 주제를 골랐는지 개인적인 판단으로 시작한다.
2. 최근 신호 TOP 3가 있으면 말로 먼저 소개한다.
3. 표는 정리용으로만 넣고, 본문은 해석 중심으로 쓴다.
4. 종목별로 `차트 위치 -> 신호 의미 -> 뉴스/공시 연결 -> 아쉬운 점 -> 다시 볼 기준` 순서로 쓴다.
5. 최근 신호 종목이 부족하면 ETF/섹터 흐름을 시장 방향성 관점에서 설명한다.
6. 면책/주의 문구는 글 앞이 아니라 마지막에 자연스럽게 붙인다.

## Layout Template

project300 티스토리 글은 아래 레이아웃을 기본값으로 사용한다.

1. Hero thumbnail
   - 썸네일 이미지를 첫 화면에 배치한다.
   - 바로 아래에서 오늘 왜 이 글을 쓰는지 설명한다.
2. Opening note
   - `오늘은 이 종목들이 먼저 눈에 들어왔습니다`처럼 개인 판단으로 시작한다.
   - 검색 키워드는 자연스럽게 넣되, 문장 첫머리를 면책 문구로 시작하지 않는다.
3. Summary table
   - TOP 3 또는 ETF 핵심 리스트를 표로 정리한다.
   - 표는 정리용이고, 본문 해석을 대체하지 않는다.
4. Stock review block
   - 종목명 H2 다음에 차트 이미지를 먼저 넣는다.
   - 이미지 직후 `이 차트에서 제가 먼저 보는 부분은...` 식의 해석 문단을 붙인다.
   - 이후 `차트 위치 -> 신호 의미 -> 뉴스/공시 연결 -> 아쉬운 점 -> 다음 체크` 순서로 쓴다.
5. ETF/sector block
   - ETF 보드 이미지를 먼저 보여준다.
   - 어떤 섹터가 위로 올라왔는지, 왜 오늘 시장 방향을 보는 데 도움이 되는지 설명한다.
6. Closing note
   - 내일 다시 볼 기준을 적는다.
   - 마지막에 투자 판단 안내를 자연스럽게 넣는다.

## Image And Chart Explanation

- 이미지를 넣은 직후 반드시 설명 문단을 붙인다.
- 목록/보드 이미지는 `오늘 리스트의 분위기`를 설명한다.
- 종목 차트 이미지는 `왜 이 종목을 따로 열어봤는지`를 설명한다.
- 이미지가 흐릿하거나 작게 보일 수 있으므로 핵심 숫자와 해석은 본문에 다시 적는다.
- alt text와 caption에는 날짜, 종목명 또는 ETF명, 신호/차트/보드 역할을 포함한다.

## Voice Anchor

Project300 글은 반말 메모체가 아니라 존댓말 기반의 설명형 블로그체를 따른다.

대표 흐름:

- `오늘은 ... 확인해 보도록 하겠습니다.`
- `뭔소리냐구요? 그냥 지표 차트를 봅시다.`
- `간단하게 말하면 ... 라는 겁니다.`
- `자. 그럼 ... 볼까요?`
- `이런....`
- `ㅎㅎ`
- `보완이 필요해 보입니다.`
- `다음 포스팅에는 ... 적어 보겠습니다. 감사합니다.`

이 말투는 `오늘의 관심종목 리뷰`, `종목별 신호 집중분석`, `ETF 섹터 흐름 리뷰`, `선물·옵션 시그널 기록` 네 카테고리 모두에 적용한다.

## Narrative Pattern Bank

종목/ETF 설명은 한 가지 고정 문단을 반복하지 않는다.

- 종목 설명은 10개 이상의 deterministic narrative pattern 중 하나를 고른다.
- ETF 설명도 10개 이상의 deterministic narrative pattern 중 하나를 고른다.
- 선택 기준은 날짜, 종목/ETF 코드, 이름을 사용하므로 같은 날 같은 대상은 안정적으로 같은 말투를 쓰고, 대상이 달라지면 문장 흐름도 달라진다.
- 패턴은 `차트 체크리스트`가 아니라 사람이 화면을 보며 이야기하는 흐름이어야 한다.
- 예시 흐름:
  - `요즘 금융주가 자주 상위 후보에 올라오네요. 최근 흐름이 좋은 것 같습니다. 먼저 하나금융부터 볼까요?`
  - `11만원에서 12만원 사이에 매수 타점이 많이 보입니다. 곧 올라가려나요?`
  - `이평선 위로 주가가 올라온 상태이니 조금 기대해봐도 좋을 것 같습니다.`
  - `그러면 이제 최근 기사나 공시도 좀 살펴볼까요?`
- ETF는 `ETF는 개별 종목처럼...` 같은 설명문보다 `오늘은 종목보다 시장 방향을 먼저 보는 날`처럼 시작한다.
- 각 종목/ETF 문단에는 급등포착 또는 종목 상세 화면 링크를 자연스럽게 포함한다.

## Cross-Category Internal Links

Project300 글은 한 글에서 끝나지 않고 네 카테고리를 순환 참조한다.

- `오늘의 관심종목 리뷰`는 넓게 본 관심종목 리스트로 연결한다.
- `종목별 신호 집중분석`은 최근 매매 신호가 나온 종목을 깊게 보는 글로 연결한다.
- `ETF 섹터 흐름 리뷰`는 종목 신호가 애매하거나 시장 방향을 먼저 볼 때 연결한다.
- `선물·옵션 시그널 기록`은 나스닥 선물, S&P500 선물, 코스피 선물 등 큰 흐름과 ETF/국내주식 해석을 연결하는 글로 연결한다.

선물·옵션 신호 데이터가 아직 준비되지 않은 동안에는 현재 발생한 신호처럼 쓰지 않는다.

예시:

```text
나스닥 선물 쪽에서 매수 타점이 포착되는 날에는 미국 ETF가 더 매력적으로 보일 수 있습니다.
반대로 선물 흐름이 약하면 ETF 신호도 조금 더 보수적으로 봐야 합니다.
```

이 문장은 조건부 해석으로 사용하고, 실제 신호가 연결되면 해당 카테고리 글로 링크한다.

## Required CTA

모든 카테고리 글에는 아래 의미의 CTA를 자연스럽게 포함한다.

```text
혹시 손실이 잦다면 혼자 감으로 거래하기보다, 급등포착에서 진입가·목표가·손절선과 매매 타점을 같이 확인해 보시는 것도 좋겠습니다.
```

표현은 매번 같을 필요는 없지만 `손실`, `급등포착`, `매매 타점 또는 진입/목표/손절 기준`, `확인해 보라`는 의미가 들어가야 한다.

수익 보장, 매수 지시, 확정 수익 표현으로 쓰지 않는다.

## SEO Filter

- 제목에는 핵심 키워드, 종목명 2~3개 또는 ETF/섹터명, 날짜, 급등포착을 포함한다.
- 첫 300자 안에 `국내주식`, `관심종목`, `급등포착`, 핵심 종목명 또는 ETF명을 자연스럽게 넣는다.
- H2에는 검색 의도를 반영한다.
- 본문에는 급등포착 원문 링크, 뉴스/공시 출처 링크, 차트 이미지 alt 텍스트를 포함한다.
- Blogger용 TOP 8 브리핑과 같은 제목/문단 구조를 쓰지 않는다.
- 썸네일, 차트, ETF 보드 이미지는 각각 다른 설명 역할을 가져야 한다.
- 마지막에는 판단 책임 안내를 두되, 본문 전체가 방어 문구처럼 보이지 않게 한다.

## Banned Or Weak Phrases

아래 문구는 project300 Tistory 글에서는 피한다.

- `관찰 후보`
- `정보성 참고자료`
- `단순 여력`
- `상위 3개가 먼저 보이는 이유`
- `종합점수 기준으로 정렬한 관찰 대상`
- 글 첫머리의 `본 자료는 투자 권유가 아닙니다`
- 글 첫머리의 `투자 판단은 본인 책임입니다`

주의 문구 자체는 필요하지만 마지막 마무리 문단에 자연스럽게 넣는다.

## Generation Prompt

```text
당신은 project300.tistory.com에 오래 기록해 온 개인 시스템트레이딩 블로그 작성자다.

기존 글의 핵심은 문장 복제가 아니라 설명 방식이다. 차트를 보고, 숫자를 해석하고, 아쉬운 점까지 개인 기록처럼 풀어낸다.

글은 SEO를 의식하되 검색어만 쌓지 않는다. 제목/H2/첫 문단/이미지 설명/출처 링크로 검색 의도를 해결한다.

문장 톤은 `오늘 저는 이 부분을 먼저 봤습니다`, `자 그럼 차트를 보겠습니다`, `이 숫자는 좋아 보이지만 여기서 조심할 점은` 같은 흐름을 따른다.

표와 수치는 정리용으로 쓰고, 본문에서는 왜 그 숫자가 의미 있는지 설명한다.

최근 신호 TOP3 종목이 있으면 각 종목을 깊게 설명한다. 신호 종목이 부족하면 ETF/섹터 흐름으로 오늘 시장의 방향을 읽는다.

직접적인 매수/매도 지시, 수익 보장, 확정 급등 표현은 쓰지 않는다.

주의 문구는 첫 문단이 아니라 마지막 `마무리`에 자연스럽게 넣는다.
```

## Review Checklist

- 제목이 검색 가능한가?
- 첫 문단에 오늘 글의 이유와 핵심 키워드가 들어갔는가?
- 표보다 해석 문단이 더 중요한가?
- 종목별로 차트, 신호, 뉴스/공시, 아쉬운 점, 다음 확인 기준이 연결되는가?
- 기존 project300 글처럼 사람이 설명하는 느낌이 나는가?
- Blogger Daily Brief와 중복 글처럼 보이지 않는가?
- 급등포착, 뉴스, 공시 출처 링크가 있는가?
- 이미지가 흐름상 필요한 위치에 들어갔는가?
- 위험 고지/판단 책임 안내가 글 마지막에 자연스럽게 들어갔는가?
- 금지 문구와 확정 수익 표현이 없는가?

## Review Rewrite Loop

- 1차 검수는 `src/lib/tistory/project300-style-review.ts`의 deterministic 체크리스트로 수행한다.
- 기준 점수 미달이면 `style_rewrite` LLM task route를 사용해 GPT CLI 재작성 후보를 만들 수 있다.
- GPT CLI 검수/재작성 프롬프트에는 위 Voice Anchor 예시와 Required CTA 정책을 함께 넣는다.
- GPT CLI 실행은 기본값이 preview-only이며, `PROJECT300_GPT_CLI_STYLE_REWRITE_ENABLED=true`와 확인 문구 `PROJECT300 GPT CLI REWRITE`가 있을 때만 수행한다.
- 재작성 후보는 숫자, 날짜, 링크, 이미지 참조를 바꾸지 않고 말투와 설명 흐름만 고친다.
- 재작성 후 같은 체크리스트로 다시 검수하며 최대 3회 반복한다.
- `llm_call_logs` metadata에는 prompt/raw response/candidate 전문을 저장하지 않고 hash/length/score만 저장한다.

## Implementation Notes

- 코드 상수는 `src/lib/tistory/project300-style.ts`에 둔다.
- export metadata는 `src/lib/tistory/project300.ts`에서 스타일 프로필과 SEO 체크리스트를 포함한다.
- Content Detail의 `Tistory HTML Export` 블록에서 적용된 style profile과 체크리스트를 표시한다.
- Content Detail의 `Tistory HTML Export` 블록에서 layout template과 image explanation policy도 표시한다.
- Content Detail의 `Tistory HTML Export` 블록에서 Project300 style/SEO review score와 GPT CLI rewrite loop policy도 표시한다.
- Tistory 카테고리명은 실제 생성된 값에 맞춰 `ETF 섹터 흐름 리뷰`를 사용한다. Tistory 카테고리명에는 `/`를 쓰지 않는다.
